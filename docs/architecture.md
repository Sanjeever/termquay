# 架构约束与设计理由

本文维护 TermQuay 的设计意图、长期约束和行为契约。“必须”“不得”和目标描述约束后续实现，不表示所有能力已验收。当前实现细节以代码及有效测试为准。调整既有决策时，记录原因、受影响契约与必要迁移，避免用实现现状抹掉约束。

## 产品与技术边界

TermQuay 面向个人桌面的 SSH/RDP 连接管理。外层标签保留固定连接中心入口与连接工作区，SSH 内层标签表示独立终端或文件。连接中心集中管理分组、搜索、筛选和连接操作，远端文件与监控属于连接工作区。两者分开，避免连接目录与文件浏览互相替换，使连接切换和服务器内操作各有稳定入口。切换面板、标签和设置保留会话所有者；监控订阅跟随当前工作区实际可见性。持久配置、运行时会话和本机布局分别管理；恢复布局不等于恢复远端 Shell，不自动重放输入或命令。

采用单机 Go/Wails 应用，React 管理视图与编辑草稿，Go 管理连接、认证、传输、采集、存储和备份。不引入账号服务、云端控制面、分布式服务、通用插件框架或团队同步系统。连接配置数量无商业限制；网络会话、任务、缓冲和排队仍必须有界，不能把产品不限量解释为运行资源无限。

SSH、SFTP、终端模拟、编辑器和 RDP 分别复用成熟协议库及组件。具体依赖与兼容组合由 [go.mod](../go.mod)、[前端清单](../frontend/package.json) 和锁文件固定。CodeMirror 面向配置文件编辑，不扩展为 IDE 服务。协议、ASN.1、SQLite、加密和快照封装不另造解析器或密码算法。

## 通信、背压与生命周期

- 控制操作使用 Wails 服务绑定，低频状态使用事件，终端字节使用有序、有界的 Streams。接口与类型从 Go 生成绑定，不能手工维护两套跨语言定义。
- Streams 队列有界不足以保证端到端背压。xterm.js 的写入会排队，必须在解析完成回调中确认已消费字节，上游收到确认后再继续。输出积压不能阻塞独立的输入接收路径，不能静默丢弃未解析输出。
- 一个 SSH 工作区可以复用底层连接，每个终端必须拥有独立 PTY；SFTP 和监控使用独立通道，不向交互终端插入后台命令。关闭单个终端不能顺带关闭整个工作区连接。
- 会话必须有明确所有者和关闭路径。取消、断线、关闭工作区、前端销毁及程序退出均需释放相关连接、通道、goroutine、订阅和前端实例。切换标签保留会话，收起传输面板不取消任务；关闭所属工作区则取消传输并尝试清理暂存文件。
- 服务端通道上限和本机资源都有限。并发、帧大小与超时由代码约束，不在文档维护第二套数值；改变这些参数时仍须满足交互响应与资源回收契约。

RDP 图形队列与 WASM 内存也属于资源边界，其上界需要持续真实图形负载验证，不能从 SSH 的背压测试推断相同保证。

界面工作区 ID 与 SSH 连接实例、PTY ID 分开。原地重连先释放旧网络资源，再显式建立新实例，不复用旧 Stream、PTY 或输入；旧终端保留有界本地缓冲供查看。目录与草稿属于稳定界面，重连后逐文件重新核对远端基线；基线变化时阻止直接保存。草稿退出保护属于已注册的界面工作区，网络断开不能解除保护；关闭界面后拒绝旧异步更新恢复该保护。

## 身份、凭据与本地数据

本地业务数据使用 SQLite，凭据字段采用 AEAD 加密，随机主密钥由系统密钥库保护。连接名称、地址等元数据不是整库加密。主密钥不写入数据库，数据库版本独立于应用版本；未知未来版本必须报错，不能作为空库覆盖。

系统密钥库不可用时必须明确处理，不能退回明文持久化。当前提供会话存储，数据库位于临时目录，凭据仍加密，随机密钥留在进程内，正常退出时清理；会话模式不提供重启恢复保证。密码解锁是可另行实现的路径，当前没有该入口。

连接目录接口不返回秘密。已保存 SSH 凭据的解密与认证留在 Go，前端不读取已保存的 SSH 密码或私钥；手工输入经连接表单提交。RDP WASM 必需的认证材料限于创建流程，不进入 React 全局状态、日志或持久化。退出时释放引用，但不承诺进程、JavaScript 或 WASM 内存中绝无明文或能立即可靠擦除。

SSH 首次连接由用户核对并确认主机指纹，已知密钥变化必须阻止连接。RDP 首次证书可由系统 CA 与主机名验证；无法通过该验证的证书需用户核对指纹，已过期或尚未生效的证书不能通过手动信任绕过。两类 RDP 信任路径均固定证书指纹，后续变化阻止连接。合法身份更换需要可审阅的信任管理，当前该管理入口仍待实现，不能自动接受新身份。

信任记录属于本机设置，默认不随快照覆盖。连接稳定 ID 与目标地址职责不同，不以主机地址作为连接配置的唯一身份。

## 远端文件与监控

手动目录同步先扫描与预览，再显式执行选中差异。比较相对路径、大小和秒级修改时间，不删除目标多余文件，不跟随符号链接；执行前及发布前复核源/目标，普通 SFTP 检查与重命名之间仍无原子 CAS 保证。扫描与计划有条数、层数、路径字节、时长和并行计划限额；目录作为一项队列任务逐文件流式执行，失败报告已完成数量并要求重新预览剩余差异，不自动重放旧计划。

现用 SFTP v1 的 ReadDir 会累积完整目录，不能靠读取后的条数检查限制这部分内存。同步扫描单独采用同一上游 SFTP v2 的分页 API，并限制包和在途请求；现有文件传输保留 v1。v2 当前为预发布版本，该选择限于分页扫描需求，需保留分页、取消、关闭与真实服务端回归；上游 v1 提供可限量读取或 v2 稳定后重新评估，不能静默取消扫描边界。

远端路径使用 POSIX 语义，文件名不得直接拼接进 Shell 命令。文件草稿由前端持有，后台刷新、状态事件和保存失败不能覆盖草稿；关闭文件、工作区或应用前明确处理未保存内容。

在线编辑面向受大小限制的 UTF-8 普通文件，符号链接需显式使用实际目标路径。当前用户可见限制为 2 MiB，定义在 [远端文件服务](../internal/files/service.go)。保存核对内容及属性版本，在同文件系统写入私有暂存目录后用服务端 POSIX rename 替换，保留服务端报告的 POSIX 权限、UID/GID，拒绝保存含特殊权限位的文件。

私有暂存目录用于防止内容在最终权限设置前暴露。当前 SFTP 创建接口不能在创建文件时指定权限，因此先限制目录访问，再写入内容；允许其他用户改写且没有 sticky bit 的目标目录会被拒绝。网络中断可能遗留私有暂存目录。普通 SFTP 无法保证与外部写入者原子地执行“版本未变才替换”，检查与替换间仍有竞争窗口；当前也不保留 ACL 和扩展属性。这些限制不能被描述成完全无损或绝无冲突的保存。

监控首版面向 Linux，通过独立 exec 通道将内置脚本经 stdin 发送，不安装远端常驻组件或落地脚本。采集随面板订阅启停，速率由计数差和时间差得到。首次采样、计数重置或采集失败必须显示未知或错误，不能把缺失数据当作零，或把旧样本冒充实时数据。采集应按数据更新频率调度，并合并同目标订阅以避免重复工作。

## 内嵌 RDP

IronRDP WASM 承担桌面协议与渲染，Go 提供 RDCleanPath 桥接。WebView 不能直接建立原始 TCP/TLS 连接，因此使用本地回环 WebSocket 承接浏览器传输，由 Go 完成目标协商与 TLS，再连接 WASM 所需的数据链路；普通 WebSocket/TCP 转发不能替代 RDCleanPath。

桥接必须限制为回环监听，校验来源及会话授权。短期一次性授权绑定后端确定的具体目标，未通过授权不能连接目标，不开放任意目标代理。TLS/NLA 必须保留，不能为打通目标降级。

当前桥接显式使用 TLS 1.2，不自动重试其他协议。Windows 11 目标在 Go TLS 1.3 握手完成后、首个认证数据发送前返回 `internal_error`，相同证书、账户和组件在 TLS 1.2 下建立桌面；这是互操作限制，不能归因于密码错误。TLS 1.3-only 目标当前无法连接。调整版本边界须重新验证真实目标的握手、NLA、画面和输入，继续保留证书指纹、有效期和身份变化阻断。

JS、桌面组件与 WASM 必须使用已核对的兼容组合，资源随应用分发。WASM 装载、本地 TLS 桥接和真实 RDP 桌面是不同验收层次；剪贴板默认关闭，用户按会话开启文本剪贴板。各平台仍需验证焦点、中文输入、剪贴板权限、尺寸与多会话行为。若该方案实测无法满足目标，先整理具体证据与契约影响再调整架构。

桌面组件的 `ready` 先于异步剪贴板初始化。当前通过 [固定版本补丁](../frontend/patches/@devolutions__iron-remote-desktop@0.11.0.patch) 增加 `clipboard-ready` 事件，应用先关闭自动同步，再等待回调注册完成后连接，避免认证启动时遗漏剪贴板回调。补丁由 pnpm 锁定与应用，未升级依赖；更换兼容组合前须核对上游就绪契约并验证手动剪贴板，不能用固定延时替代就绪信号。

## 加密备份与恢复

快照是带版本的 JSON 经 `age` 加密，包含来源设备、创建时间、分组、连接及用户选择携带的凭据。导出需获得一致性视图，明文不落临时文件。恢复秘密独立于本机系统密钥库，确保另一设备能够解密；当前实现使用独立备份密码，尚无单独恢复密钥入口。仅备份原设备加密后的凭据字段无法满足跨设备恢复。

WebDAV 使用追加式快照，不覆盖或自动清理历史。备份目录由用户指定，相对 WebDAV 基址解析。曾验证的服务商忽略 PUT 创建条件，所以当前先上传临时密文，再用 `MOVE` 且 `Overwrite: F` 发布。此步骤直接发出单次请求，避免依赖库递归重试同名冲突。更换实现时仍须证明同名拒绝、原快照不变和失败可清理，不能把请求头存在当作服务商遵守契约的证据。

恢复顺序是解密、验证版本与引用、展示差异、用户确认、事务替换分组、连接和凭据。提交必须对应预览的同一份已解密数据，预览失效或本地配置已变化时拒绝提交。凭据使用目标设备主密钥重新加密，失败不能部分覆盖现有数据。

恢复是替换，不是合并；即便快照未携带凭据，也会替换本地连接凭据集合。本机设置、WebDAV 登录配置、主机与证书信任默认保留，不纳入恢复替换。私钥内容是否携带由用户选择，引用本机路径不代表内容已备份。上传失败不撤销本地修改；后续自动备份需串行、合并等待任务，不能由监控或进度更新触发循环，不做无界重试。

字段、格式版本、大小限制和预览时效以模型、校验与测试为准。修改这些定义须考虑现有数据库、快照和已生成接口的兼容性。
