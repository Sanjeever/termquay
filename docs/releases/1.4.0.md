## English interface

- Add offline English and Simplified Chinese interfaces. Choose **Settings → Appearance → Language** to follow the system or select a language explicitly. The preference applies before storage unlock.
- Translate connection and file workspaces, terminal tools, diagnostics, AI views, settings, native menus and application-owned file dialog labels. Language changes preserve workspace identity, editor drafts, selection, undo history and open searches.
- Add English development and architecture guides, with Chinese entry points and bilingual contribution guidance. This release addresses the [English UI request (#1)](https://github.com/Sanjeever/termquay/issues/1).

## Docker workspace

- Open Docker from **Tools → Docker**, SSH session actions or command search in a dedicated tool tab. Browse and filter containers, inspect resources, health, mounts and ports, read logs and add them to multi-source logs.
- Open independent `/bin/sh` or `/bin/bash` container terminals; switching containers or hosts preserves open terminals. Start, stop and restart require confirmation of the actual SSH target and container.
- Save custom or rootless socket paths per SSH connection. Queries use Docker HTTP over an existing verified SSH connection, without installing remote dependencies. CLI and AI container queries require their own socket argument.

## Other changes

- Adjust AI provider output token limits and improve settings navigation icons.
- Consolidate duplicated documentation and verification records, and clarify CLI response fields, socket selection and documentation synchronization rules.

## Verification and limits

- Existing [localization](https://github.com/Sanjeever/termquay/blob/v1.4.0/docs/development.md#localization-verification-2026-11-09) and [Docker](https://github.com/Sanjeever/termquay/blob/v1.4.0/docs/development.md#docker-workspace-verification-2026-11-09) records distinguish automated checks, browser substitutes and Windows native verification. They do not establish live remote language switching or real Docker/SSH acceptance.
- Real Docker/SSH, model services, macOS/Linux native interactions, IME/screen readers and sustained application-wide resource behavior still need scenario-specific verification. Embedded RDP retains its [TLS compatibility boundary](https://github.com/Sanjeever/termquay/blob/v1.4.0/docs/architecture.md#embedded-rdp).

- 新增离线英文与简体中文界面，在“设置 → 外观 → 语言”选择跟随系统或指定语言，解锁存储前即可生效。

## Docker 工作区

- 从“工具 → Docker”、SSH 会话菜单或命令搜索打开独立工具标签，浏览、筛选容器，查看资源、健康状态、挂载与端口，读取日志并加入多来源日志。
- 支持独立的 `/bin/sh` 与 `/bin/bash` 容器终端，切换容器或主机保留已打开终端。启动、停止和重启前须核对实际 SSH 目标与容器。
- 按 SSH 连接保存自定义或 rootless socket 路径，经已验证的 SSH 连接访问 Docker HTTP API，无需安装远端依赖。CLI 与 AI 容器查询需各自指定 socket 参数。

## 其他变更

- 调整 AI 服务商输出 token 限额，改进设置导航图标。
- 合并重复文档与验收记录，明确 CLI 响应字段、socket 选择及文档同步规则。

## 验证与限制

- 既有[本地化](https://github.com/Sanjeever/termquay/blob/v1.4.0/docs/development.md#localization-verification-2026-11-09)与 [Docker](https://github.com/Sanjeever/termquay/blob/v1.4.0/docs/development.md#docker-workspace-verification-2026-11-09)记录区分自动检查、浏览器替身和 Windows 原生验证，不能据此认定活动远端语言切换或真实 Docker/SSH 已通过。
- 真实 Docker/SSH、模型服务、macOS/Linux 原生交互、输入法、屏幕阅读器及整个应用的持续资源负载仍需专项验证。内嵌 RDP 保留既有 [TLS 兼容边界](https://github.com/Sanjeever/termquay/blob/v1.4.0/docs/architecture.md#embedded-rdp)。
